# 网络诊断雷达

入口：[NetworkRadar.yaml](NetworkRadar.yaml)，脚本：[NetworkRadar.js](NetworkRadar.js)。
这些非规则资源从 `master` 发布，不进入 `auto-build`。

## 布局与检测

- 中号保留图标及蓝色本地 / 紫色代理双列：本地环境、内网、公网、位置、运营商、延迟；代理出口、落地、组织、ASN、策略、延迟。下方只显示一次出口属性、IPPure 风险及六项影视 / AI 结果。
- 大号增加网关、两行完整出口 IP / 组织及检测时间；属性、评分、AI 不再重复。长 IPv6 在中号明确缩略，大号最多两行。长名称可能省略尾部。
- 本地信息和延迟固定 `DIRECT`；出口及服务使用模块参数 `RADAR_POLICY`，默认 `Proxy`，须在当前配置存在。所有服务测的是这个指定策略，不自动追随各服务分流组。
- IPPure 同一次响应提供 IP、ASN、组织、地区、住宅属性、评分。IPPure 失败时保留原 ip-api HTTP 接口作备用，但清空住宅属性和评分，不沿用旧 IP 的评分。`isResidential` 只表示住宅分类，不证明“原生 IP”。
- 风险按 IPPure 分数显示：0..39 低、40..69 中、70..100 高，数值缺失、类型错误或超界显示无数据。这是第三方评分，不是安全保证。
- `✓` 为 HTTP 探测可达，`×` 为检测到地区受限信息，`◐` 为 Netflix 仅备用片目页面可达，`?` 为超时、限流、验证页或证据不足，`—` 为关闭检测。页面可达不证明播放、登录或订阅可用。地区只显示接口实际返回的地区，不把出口地区复制给所有服务。

## 刷新与缓存

普通组件每次运行重新查询出口 IP 和代理延迟；本地信息默认缓存 60 秒，服务结果按项缓存 600 秒，未知结果最多缓存 30 秒。缓存范围包含当前网络、指定策略及出口 IP；同名策略切换后，只要出口改变就重新检测。没有可靠的节点描述符 API，因此相同出口 IP 背后的节点变化无法区分。负载均衡策略可能让不同请求使用不同出口，此模块不保证这些请求固定到同一节点。

“网络诊断雷达 · 立即检测”跳过缓存并返回同一组件。服务检测可以独立关闭；关闭后不请求服务站点。缓存为 Egern 本机 `NetworkRadar.v2`，存储不可用时直接检测，不输出原始错误。IP 打码只影响显示，本机缓存仍含检测地址。

大号底部显示服务结果最早的检测时间；中号 `AI·缓` 表示服务区有缓存结果。顶部时间是本次运行时间，不是所有服务的重新检测时间。`refreshAfter` 请求一分钟后刷新，实际调度由 iOS 决定；模块/脚本 `update_interval` 是源码更新间隔，与检测频率不同。

## 维护边界与验证

本模块不修改分流规则、DNS、MITM、PO0 账号或官方白名单；PO0 上报由独立模块维护。已关闭的旧 IP 信息面板 / IPPure 不需要重新启用。

```text
node --test Egern/Modules/tests/network-radar.test.mjs
```

测试使用模拟接口及本机存储，覆盖出口变化、缓存失效、评分隔离、超时/挑战页和中大号布局。浏览器 DSL 预览用于版式检查；最终字体、SF Symbols、截断和后台刷新仍需 Egern 设备核对。

API 依据：[Egern JavaScript](https://egernapp.com/zh-CN/docs/javascript-api/)、[Widget DSL](https://egernapp.com/zh-CN/docs/configuration/widgets/)。
