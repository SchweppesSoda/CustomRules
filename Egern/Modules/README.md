# 网络诊断雷达

入口：[NetworkRadar.yaml](NetworkRadar.yaml)，脚本：[NetworkRadar.js](NetworkRadar.js)。
这些非规则资源从 `master` 发布，不进入 `auto-build`。

## 布局与检测

- 中号保留图标及蓝色本地 / 紫色代理双列：本地环境、内网、公网、位置、运营商、延迟；代理出口、落地、组织、ASN、策略、延迟。属性和评分一行，六项服务合并为一行文字；保留标题、正文和属性图标，服务行省去重复图标与分类标签。
- 大号两列各七行：本地增加网关，代理增加信息来源，延迟统一位于末行。所有字段（包括出口 IP、落地、组织）统一单行，超宽截断；不换行、不缩小字号。标题 20 pt、正文数值 12 pt；属性与 IPPure 评分左右等分，影视 / AI 各一行三格，服务区从 70 pt 压至 38 pt，移除独立厚卡片。
- `20260909-radar-v2.4` 重新分配高度：中号标题 17 pt、标题区 30 pt，底部 8 pt 留白；大号标题区 34 pt。正文改为逐行左右配对的平面表格，承接根容器剩余高度，再按行分配；每个数据单元格仍明确保留中号 13 pt / 大号 20 pt 的可读高度。较高组件的多余空间分配给正文，不在底部堆积。根容器最低预算中号 152 pt、大号 325 pt；服务区固定占用中号 14 pt / 大号 38 pt，不随高度拉伸。
- `20260909-radar-v2.5` 保留上述字号、行距和高度预算，参考 PO0 上报的渐变底与圆角色块：正文背景区分蓝色本地 / 紫色代理，大号分区标题使用更明显的同色底；属性和评分按状态使用绿、琥珀、红或中性色，影视 / AI 使用蓝 / 紫色小块。浅色、深色分别配色；正文与大号服务格仅增加左右 4 pt 内边距，不增加垂直占用。背景直接绘制在原平面表格上，不恢复嵌套弹性卡片。
- 本地信息和延迟固定 `DIRECT`；出口及服务使用模块参数 `RADAR_POLICY`，默认 `Proxy`，须在当前配置存在。所有服务测的是这个指定策略，不自动追随各服务分流组。
- 出口默认查询 IPv4：先请求 `https://my.123169.xyz/v1/info`（[clash-ip-checker 采用的 IPPure 镜像](https://github.com/tombcato/clash-ip-checker/blob/docker/core/sources/ippure.py)），失败再尝试 `my.ippure.com/v1/info`，最后使用原 ip-api HTTP 备用接口。2026-09-09 核验镜像无 AAAA、HTTPS 返回 IPv4 及 IPPure 字段；所有响应仍必须校验为 IPv4，不能仅依赖域名的地址族。均失败时显示 `IPv4 未知`，不回填 IPv6、不继续服务检测。
- IPPure 同一次响应提供 IP、ASN、组织、地区、住宅属性、评分。ip-api 备用响应会清空住宅属性和评分，不沿用其它 IP 的评分。`isResidential` 只表示住宅分类，不证明“原生 IP”。[IPPure 官方说明](https://ippure.com/faq)不计算 IPv6 的 IPPure 系数。
- IPv4 查询约束只针对出口信息：Egern 公开的 `ctx.http` 没有逐请求指定地址族的参数，影视 / AI 仍通过指定策略连接原站点，不能保证各站请求均为 IPv4，结果不应当作已确认的“IPv4 解锁”。模块不修改全局 IPv6 或 DNS 设置。
- 风险按 IPPure 分数显示：0..39 低、40..69 中、70..100 高，数值缺失、类型错误或超界显示无数据。这是第三方评分，不是安全保证。
- `✓` 为有服务页面证据的 HTTP 可达，`×` 为明确地区受限，`◐` 为 Netflix 一个样本片目 404、另一个可达，不代表“仅自制剧”。紫色地区码（不加勾）仅为地区信息；页面可达或地区信息均不证明播放、登录或订阅可用。地区只显示接口实际返回的地区，不把出口地区复制给所有服务。
- 未知状态显示具体原因：`验证`、`连接`、`超时`、`限流`、`跳转`、HTTP 状态码、`空响应` 或 `解析`；没有出口时显示 `未测`，关闭检测时显示 `—`。不为消除问号而把 403、验证页或任意 HTML 判为可用。

## 服务探测依据

- 所有服务最多请求四跳，总预算 7 秒，单跳最多 4 秒。只跟随本站 HTTPS 域名内跳转，每一跳保留原策略、不带 Cookie；环路、跨站和降级到 HTTP 不继续请求。
- Netflix 检查两个片目页面的站点标题和片目 ID；Disney+ 检查页面标题及地区字段，或明确的 `inSupportedLocation`；TikTok 从首页解析地区字段，兼容转义 JSON 和带后缀的地区值。正常页面引用 `captcha` 库不等于验证拦截；只有验证页标题、明确挑战结构或短页面的可见提示才判为验证。
- GPT / Claude 使用各自 `/cdn-cgi/trace`，只返回地区证据；Gemini 使用首页内嵌地区数据，缺少地区字段时仅在识别到应用壳标记后报告页面可达。未维护一份假定永久有效的国家封禁列表，也不把地区结果改写成绿色“解锁”。专项接口参考：[subs-check 平台检测源码](https://github.com/beck-8/subs-check/tree/master/check/platform)。

## 刷新与缓存

普通组件每次运行重新查询出口 IP 和代理延迟；本地信息默认缓存 60 秒，服务结果按项缓存 600 秒，未知结果最多缓存 30 秒。缓存范围包含当前网络、指定策略及出口 IP；同名策略切换后，只要出口改变就重新检测。没有可靠的节点描述符 API，因此相同出口 IP 背后的节点变化无法区分。负载均衡策略可能让不同请求使用不同出口，此模块不保证这些请求固定到同一节点。

“网络诊断雷达 · 立即检测”跳过缓存并返回同一组件。服务检测可以独立关闭；关闭后不请求服务站点。缓存为 Egern 本机 `NetworkRadar.v2.3`，隔离旧版探测语义和误判结果；存储不可用时直接检测，不输出原始错误。IP 打码只影响显示，本机缓存仍含检测地址。

大号底部显示服务结果最早的检测时间；中号顶部时间后的 `· 缓` 表示服务区有缓存结果。顶部时间是本次运行时间，不是所有服务的重新检测时间。`refreshAfter` 请求一分钟后刷新，实际调度由 iOS 决定；模块/脚本 `update_interval` 是源码更新间隔，与检测频率不同。

## 维护边界与验证

本模块不修改分流规则、DNS、MITM、PO0 账号或官方白名单；PO0 上报由独立模块维护。已关闭的旧 IP 信息面板 / IPPure 不需要重新启用。

```text
node --test Egern/Modules/tests/network-radar.test.mjs
```

v2.5 通过 26 项测试，覆盖出口变化、缓存隔离、IPv4 优先、正常 CAPTCHA 资源与真实挑战页的区分、受限跳转、失败原因、地区与可达语义、中号标题间距、大号七行对应、全字段单行及不同可用高度下的空间分配。浏览器辅助检查使用 329×155 / 360×170 中号和 329×345 / 360×376 大号，包含正常、长字段和失败状态，浅色 / 深色共 24 组。根容器必须按实际组件高度分配空间，浏览器预览不得再把根容器当作内容自适应高度。

2026-09-09 使用实际脚本经桌面 HTTP 适配器验证：Netflix / Disney+ / TikTok 返回页面可达，GPT / Claude / Gemini 返回地区信息。旧判断在前三者正常页面上因 `captcha` 字符串误报验证；Claude 登录页实际返回挑战页。该验证使用桌面出口，不能代表 Egern 设备所选节点；最终字体、SF Symbols、截断及后台刷新仍需设备核对。
